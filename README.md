# Icons Home

个人图标收藏网页：浏览 / 上传图标、点击复制图标链接、一键打开跳转链接。

参考 [Siriling/my-icons](https://github.com/Siriling/my-icons) 的交互思路实现，支持**四种用法**：

1. **本地双击直开**：纯静态，无需任何服务
2. **Python 轻量服务**：本地 / 服务器一行命令启动，上传真正写入文件
3. **Docker 部署**：`docker compose up -d` 即可
4. **nginx 反代域名发布**：外网域名 / IP 均可，上传全端生效

## 特性

- **网页上传**：页面右上角「上传」按钮弹窗上传——点击选择文件或直接拖拽，选择分类后自动刷新
  - 服务模式（http/https 访问）：图片直接写入服务器 `icons/`，记录写入 `data/uploads.json`，**所有访问者都能看到**
  - 静态模式（file:// 双击打开）：降级为浏览器本地存储，免服务可用
- **分类自由**：网页「设置」面板可直接**添加 / 删除分类**（基础分类、自定义分类都可删，服务模式持久化到服务器，所有人可见）
- **图标删除**：网页上传的图标悬停显示删除按钮，一键删除（服务模式同步删除服务器 `icons/` 文件与记录）；data.js 默认图标也可删除（从页面隐藏）
- **自动排序**：支持**按名称（英文 a-z / 中文按拼音）或按添加时间**排序，可切换升序 / 降序
- **站点名称自定义**：网页「设置」可自定义网页标题与左上角名称（服务模式对所有访问者生效）
- **上传自定义链接**：上传弹窗可为每个图标填写跳转链接（输入框独立一行），上传后用卡片右上角按钮一键打开
- **日间 / 夜间 / 跟随系统**：设置面板一键切换网页明暗主题，可自动跟随设备外观
- **整理模式**：左下角「整理」按钮进入整理，当前分类图标可单选 / 多选，批量移动到任意分类或删除（工具栏限制在网页主体宽度内，超宽屏不再贴边）
- **管理员登录**：未登录仅可浏览 / 复制链接；登录后可上传、设置、整理、删除（初始账户与密码见下文「管理员登录」章节，登录弹窗不再提示；服务模式可改用户名、改密码）
- **favicon 自定义**：设置里填图标 URL 或选本地图片，浏览器标签页图标即更新
- **名称自动匹配**：图标下方名称默认与文件名一致（自动去掉扩展名）
- **点击复制、按钮跳转**：点击图标 = 复制图标链接；卡片右上角按钮 = 打开该图标自定义的跳转链接（无链接时给出提示）
- **链接自动匹配**：复制出的图标链接自动跟随当前访问地址——本地、内网 IP、外网域名切换**无需改代码**
- **零第三方依赖**：后端是单文件 Python 标准库（Python 3.8+，3.13 亦可用），不需要 pip install 任何包
- **日间 / 夜间主题**：可切换明暗背景或跟随系统，响应式布局，手机电脑都能用

## 目录结构

```
Icons-Home/
├── index.html          # 页面本体（样式 + 逻辑都在里面，一般不用改）
├── data.js             # 基础图标数据：分类、图标清单、URL 前缀（日常主要改这个）
├── icons/              # 图标图片目录：示例图标 + 上传的图片都在这里
├── data/uploads.json   # 上传记录（服务模式自动维护，首次运行自动生成）
├── data/categories.json # 网页端自定义分类（服务模式自动维护）
├── data/settings.json   # 站点设置：标题 / 隐藏的分类 / 隐藏的图标 / 移动记录 / favicon（服务模式自动维护）
├── data/auth.json       # 管理员账户（加盐哈希，服务模式首次启动自动生成 admin/password）
├── upload_server.py    # 上传服务（Python 标准库，零依赖）
├── Dockerfile          # Docker 镜像定义
├── docker-compose.yml  # Docker 一键部署（含数据持久化挂载）
└── README.md
```

## 方式一：本地双击直开（纯静态）

直接双击 `index.html` 用浏览器打开即可，不需要启动任何服务。此模式下上传的图标保存在**当前浏览器本地**（仅本机本浏览器可见）。

## 方式二：Python 上传服务（本地 / 服务器）

```bash
python upload_server.py                  # 监听 0.0.0.0:8000，托管脚本所在目录
python upload_server.py --port 9000      # 换端口
python upload_server.py --host 127.0.0.1 # 仅本机访问
python upload_server.py --dir D:\Icons-Home   # 指定项目目录
```

启动后访问 `http://localhost:8000`。上传的图片 → `icons/` 目录，记录 → `data/uploads.json`，**所有访问者刷新后都能看到**。

局域网内其它设备访问 `http://<服务器IP>:8000` 即可（需放行防火墙端口）。

## 方式三：Docker 部署

在服务器上先取得项目（`git clone` 或上传压缩包），然后：

```bash
cd Icons-Home
docker compose up -d
```

访问 `http://<服务器IP>:8000`。

- `./icons` 与 `./data` 已挂载到宿主机，**容器重建 / 升级不丢数据**
- 备份数据 = 打包这两个目录
- 查看日志：`docker logs -f icons-home`

## 方式四：nginx 反代 + 域名发布（推荐长期使用）

### 场景 A：纯静态发布（不需要上传）

把 `index.html`、`data.js`、`icons/` 整个目录放到 nginx 站点目录，如 `/var/www/icons-home`：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;
    root /var/www/icons-home;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

此方式上传走浏览器本地存储（仅当前浏览器可见）。

### 场景 B：反代上传服务（推荐，上传全端生效）

先按方式二或方式三启动服务（本机 `127.0.0.1:8000`），再配 nginx：

```nginx
server {
    listen 80;
    server_name icons.example.com;   # 域名或服务器 IP

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 20m;    # 关键：允许上传大图，否则会 413
    }
}
```

`nginx -t && nginx -s reload` 后，访问 `http://icons.example.com` 即可上传、浏览。配好 HTTPS 证书后访问 `https://icons.example.com`。

## 如何添加一个图标

### 方式 A：网页上传（推荐）

（需先登录，见「管理员登录」）点右上角「上传」→ 点击或拖拽图片 → 选择分类（可新建），可**填写自定义跳转链接（可选，输入框独立一行）**→ 开始上传，自动刷新后即生效。上传后：**点击图标 = 复制图标链接**；**卡片右上角按钮 = 打开自定义跳转链接**（未填链接时给出提示）。服务模式下图片与记录均已写入服务器。

**删除图标**：图标卡片**左上角有删除按钮**（悬停显示），点击确认即删除——网页上传的图标同步删除服务器 `icons/` 下的图片文件和 `uploads.json` 记录；`data.js` 默认图标删除后从页面隐藏（配置文件保留，重新上传同名文件或编辑 `data.js` 可恢复）。

### 方式 B：手动配置

1. 把图片文件放进 `icons/` 目录（支持 `svg` / `png` / `jpg` / `webp`）
2. 在 `data.js` 的 `icons` 数组里加一条记录：

```js
{ "category": "software", "file": "my-app.png", "link": "https://192.168.1.100:32400" }
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `category` | 是 | 所属分类 id，必须与 `categories` 里的 `id` 一致 |
| `file` | 是 | `icons/` 目录下的文件名 |
| `link` | 否 | 卡片右上角按钮打开的跳转网址（新标签页）；不填则该按钮提示无链接（点击图标始终复制图标链接） |
| `name` | 否 | 默认不写：图标下方名称自动取文件名（不含扩展名）；需要不同显示名时才加 |
| `added_at` | 否 | 手动按时间排序时用（时间戳，毫秒）；不写则按 `icons` 数组顺序 |

改完保存，刷新页面即可看到新图标。

## 图标排序

页面左侧「排序」控件：
- **按名称**：英文按字母 a-z，中文按拼音（默认）
- **按添加时间**：网页上传的按实际上传时间；`data.js` 图标如需参与时间排序，可在图标记录中加 `added_at` 字段
- 点「升序 / 降序」按钮可切换方向

## 主题切换

右上角「设置」→「外观主题」：
- **日间**：浅色背景
- **夜间**：深色背景（默认）
- **跟随系统**：自动匹配设备外观（手机 / 电脑的系统深色浅色设置）

主题偏好保存在当前浏览器，各设备可分别设置。

## 管理员登录

右上角「登录」按钮；**未登录时只可浏览图标、点击跳转链接、复制图标链接**，上传 / 设置 / 整理 / 删除等按钮均隐藏。

- 初始账户 `admin`，初始密码 `password`（服务模式存于 `data/auth.json`，加盐哈希，不存明文；**登录弹窗不显示初始账户密码，以本文档为准**）
- 登录后顶栏显示「退出 admin」，点击即退出
- 设置 →「账号安全」可**修改管理员用户名**（需输入当前密码确认）与**修改密码**；服务模式对所有访问者生效，静态双击打开时用户名 / 密码保存在当前浏览器，仅本机生效
- 服务模式登录签发 token 会话，服务重启后需重新登录；写操作接口在服务端校验登录，未登录会返回 401

## 整理模式（批量移动 / 删除）

登录后点左下角「整理」进入整理模式：

- 当前分类下的所有图标可点击选中（单选 / 多选），选中卡片带对勾标记，再次点击取消
- 左侧工具栏「移动至 [分类]」→「移动」：把选中的图标批量移动到任意分类（上传图标改服务器记录，data.js 基础图标记录移动归属）
- 右下角「删除选中」批量删除：网页上传的图标同步删除服务器 `icons/` 文件与 `uploads.json` 记录；data.js 默认图标从页面隐藏（配置保留可恢复）
- 移动 / 删除后自动刷新页面；「完成」退出整理模式

## 如何自定义 / 添加 / 删除分类

**网页端（推荐）**：打开右上角「设置」→「分类管理」：
- 输入分类名称点「添加」即新建分类（服务模式持久化到服务器 `data/categories.json`，所有访问者可见）
- 分类列表点「×」删除分类；删除时该分类下的图标自动移到「其他」
- 基础分类也可删除（在页面隐藏，`data.js` 配置保留），重新添加同名分类即可恢复
- 「其他」是兜底分类，不可删除

**编辑 data.js**：修改 `categories` 数组即可，每一行是一个分类：

```js
"categories": [
  { "id": "software", "name": "软件" },
  { "id": "mycat",    "name": "我的分类" }
]
```

- 改 `name` = 改分类名称
- 新增一行 = 添加分类
- 删掉一行（同时把图标里的 `category` 也改掉或删掉）= 删除分类

分类栏自动按此渲染并统计数量；图标排序方式见「图标排序」章节。

## 图标链接如何自动匹配（域名 / IP 通用）

页面右上角「设置」面板可查看「当前将生成」的链接格式，默认逻辑：

| 访问方式 | 复制出的图标链接 |
| --- | --- |
| 本地双击打开 | `file:///C:/…/Icons-Home/icons/文件名` |
| 本地服务 | `http://localhost:8000/icons/文件名` |
| 内网 IP | `http://192.168.1.100:8000/icons/文件名` |
| 反代域名 | `https://icons.example.com/icons/文件名` |

即：**链接永远跟随当前访问地址**，本地、内网、外网切换无需改代码。如需固定使用 CDN 或域名，可在「设置」面板填写 URL 前缀（或写入 `data.js` 的 `baseUrl` 字段）。

## 数据与备份

- `data.js`：手动维护的基础图标清单
- `icons/`：全部图标图片（示例 + 网页上传的）
- `data/uploads.json`：网页上传的记录（服务模式自动维护）
- `data/categories.json`：网页端自定义分类（服务模式自动维护）
- `data/settings.json`：站点设置——标题、隐藏的基础分类、隐藏的基础图标、图标移动记录、favicon（服务模式自动维护）
- `data/auth.json`：管理员账户（服务模式自动维护）

### 网页端备份 / 恢复（管理员登录后，设置 → 备份与恢复）

- **备份**：一键把全部图标与数据打包成 `项目名_时间戳.zip` 下载到本地。服务模式打包 `icons/` 与 `data/` 两目录；静态模式（双击打开 / GitHub Pages）打包浏览器本地数据（含上传图标的 DataURL）。
- **恢复**：选择备份的 zip 导入，自动覆盖还原。重新部署、迁移服务器后用它恢复数据最省事。
  - 服务模式：还原 `icons/` 与 `data/` 目录，**管理员账户也随备份还原**（如需保留当前密码，恢复后重新改密即可）。
  - 静态模式：还原浏览器本地数据（分类、上传记录、设置、主题、账户）。
  - 两种模式的备份 zip 可互相导入（服务端兼容静态 zip 格式，前端兼容服务端 zip 格式）。
- 备份 zip 里的 `data.js` 基础图标不随包导出，随代码仓库版本走；如需改基础图标，编辑 `data.js` 后重新部署即可。

## 部署到 GitHub Pages（可选）

把仓库推到 GitHub 后，在仓库 Settings → Pages 中：

1. Source 选择 `Deploy from a branch`
2. Branch 选择 `main`，目录选择 `/ (root)`
3. 保存后等待一两分钟，访问 `https://<用户名>.github.io/Icons-Home/` 即可

> Pages 为纯静态托管、无后端，上传走浏览器本地存储模式（仅当前浏览器可见）；需要全端上传请用方式二 / 三 / 四。
